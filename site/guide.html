1. What is Intern?

Intern reads a document and tells you what to call it. For each document it proposes a filename that starts with the date, writes a one-sentence description of what the document concerns, shows the verbatim excerpts from the document that support every fact it used, and attaches a confidence.

Anything it cannot back up with evidence from the document itself goes to a review list instead of being guessed at. And everything — reading, OCR, the AI model — runs on your machine. Your documents never leave it.

2. Do I need an account or sign-in?

No. There is no account, no sign-in, and no cloud service. Intern never asks for a password — not even for OneDrive or SharePoint, which it reaches through folders already on your disk (see section 6).

It makes exactly two kinds of network requests, and both happen only when you press a button: the one-time download of the AI model file, and Check for updates in Settings. Neither carries anything about your documents.

3. Installing it — what you'll experience, step by step

  1. Download the installer. Get Intern_<version>_x64-setup.exe from the download page. It runs on Windows 10 or 11, x86-64.
  2. Windows SmartScreen will warn you. You will see "Windows protected your PC" and "unrecognized app". This is expected: the installer is not Authenticode signed, because the project has no code-signing certificate. Click More info, then Run anyway.
  3. It installs per user. No administrator rights, no admin prompt.

Don't take an unrecognized-app warning lightly in general. The right response is to verify the download rather than trust it. Every published installer carries an attestation proving which repository, workflow, and commit produced those exact bytes — check it with the GitHub CLI: 

gh attestation verify Intern_<version>_x64-setup.exe --repo zgbrenner/intern

SHA256SUMS.txt, published beside the installer, catches a corrupted download — but it proves nothing about where the file came from. The attestation is the part that establishes origin.

4. First launch — the model download

The installer deliberately leaves out one thing: the AI model file, 1.19 GiB. The first time you open Intern, a setup screen asks to download it.

  • The download is resumable — if the connection drops, reopen Intern and it continues where it stopped.
  • The file only becomes active after its exact length and SHA-256 match the manifest built into the installer, so a broken or tampered download cannot be used.
  • Already have the file from another machine? Choose existing model files points Intern at it and skips the download. This is also how you install on a machine with no internet at all.

Nothing else needs installing. PDF reading, OCR, and inference all ship inside the app.

5. Using it day to day

Drag files or folders onto the window, or use Add files / Add folder. Supported formats: PDF, Word (.docx), Excel (.xlsx), email (.eml), plain text, Markdown, and scanned images (PNG, JPEG, TIFF).

Each document moves through statuses: Waiting → Processing → then one of two outcomes:

  • Ready — a name is proposed, with the supporting evidence attached and a confidence shown.
  • Needs review — something could not be verified against the document's own text. The reason is spelled out in plain language in the inspector.

Nothing on disk is renamed until you approve it. Approve one document at a time, or use Apply all ready. Every rename can be undone from Completed.

A document whose content Intern has already filed is flagged as a duplicate of the filed name instead of being renamed again.

Settings has a destination folder: leave it empty and files are renamed in place; set it and renamed files are moved there.

Intern runs a roughly 2-billion-parameter model on your CPU, so expect tens of seconds per document, processed one at a time. Leave it working through a stack — that pace is the price of nothing leaving your machine.

6. Hooking up OneDrive and SharePoint

The key idea: Intern connects through the folders the Microsoft sync client already keeps on your disk. It never talks to Microsoft's servers — there is no Graph API client, no OAuth token, no upload code — so it never asks you to sign in to Microsoft. The only thing moving files to the cloud is the OneDrive app you already run.

  1. Make the library a folder on your disk. Your personal OneDrive already is one. For SharePoint, open the document library in the browser and click Sync (or Add shortcut to OneDrive) — Microsoft's own way of putting it on your disk.
  2. Point Intern at it. In Intern's Settings, pick that folder (or any folder inside it) as the intake folder and/or the destination. Intern detects sync roots and labels the pick — "Synced with OneDrive – …", "Synced with SharePoint – …" — so you can see what you chose.
  3. That's it. Files that appear in the folder get processed; renamed files sync back to the cloud through the sync client.
What about online-only files (the cloud icon in Explorer)?

Files On-Demand is handled. The read Intern performs is exactly what makes OneDrive download the content. If the machine is offline, the document waits and is picked up once the content arrives, rather than being failed.

What are these "conflicted copy" files, and will Intern rename them?

Files like report (Jane's conflicted copy …), or a name suffixed with a teammate's machine, are OneDrive's conflict bookkeeping — not new documents. Intern counts them in Settings and leaves them alone. Resolve the conflict in the folder, and the surviving file is picked up.

7. Watching a folder (automatic intake)

In Settings, enable Watch a folder and pick the intake folder. Two requirements are enforced when you save:

  • Watching requires a destination folder.
  • The destination must be outside the intake folder — renaming in place inside a watched folder would make every result reappear as new work, so Intern refuses that configuration up front.

The watcher scans on a short interval, about every 20 seconds, and only picks a file up once its size and modified time have held still for a full interval — so a half-copied file is never read. Scan now forces an immediate pass.

8. Working as a team — several computers, one folder

Multiple machines can watch the same synced intake folder. They coordinate through a .intern folder inside it — small files the sync client replicates like anything else. Don't delete .intern casually; it is how machines avoid processing the same document twice.

  • Each document is claimed by exactly one machine — first claim wins, with a time-limited lease. If a machine crashes, its work is taken over automatically after its lease lapses (about 15 minutes).
  • By default, each machine only processes documents dropped on that machine. Turning on "Also process documents uploaded by others" makes the folder a shared work queue — with a two-minute courtesy delay, so the uploader's own machine gets first claim on its own work.
  • Name your machine in Settings (This machine's name) so teammates can see who is working on what.

What the shared .intern folder exposes to everyone who can see the folder: filenames, file sizes, machine names, and usernames — never document content, text, or AI output.

9. Troubleshooting

Windows says "Windows protected your PC"

Expected — the installer is not Authenticode signed. Click More info, then Run anyway. If in doubt, verify the download first with the attestation command in section 3.

The model download stopped partway

Reopen Intern — the download resumes where it stopped. The file is verified against its exact length and SHA-256 before it is ever used, so a broken download can't be used by accident.

A document says "Another program is still holding this file open"

Usually the sync client, mid-upload. Intern already waited a few seconds for the lock to clear before reporting this. Retry once the sync settles.

A document went to review — is that an error?

No. It means one of the facts in the proposed name could not be matched word-for-word in the document — the review reason says which one: the date, the document type, a party, or the description. Fix the name yourself in the inspector and approve it, or choose Keep original.

A file in my watched folder isn't being picked up

Work through the usual causes:

  • Is it a supported format? Is it zero bytes?
  • Is it still copying or syncing in? A file is only picked up once its size and modified time have held still for a full scan interval.
  • Is it a dot-file, or an Office lock file starting with ~$? Those are ignored on purpose.
  • Did another machine claim it? Settings shows the counts.

Then try Scan now.

The watched folder settings won't save

The destination folder must exist and must be outside the intake folder. Intern refuses the loop at save time and tells you which rule was hit, rather than discovering the problem while running.

A cloud file failed while I was offline

It is held, not abandoned. Reconnect, and it is retried automatically on a later scan once the content arrives.

A document failed twice and stopped

It is in Failed, with the reason shown. Retry it manually from there.

Everything is slow

Local CPU inference is the price of nothing leaving your machine. Tens of seconds per document is normal, and the app processes one document at a time on purpose.

Check for updates fails

It is the only network call Intern makes besides the model download, so check your connectivity. An update that is not signed by this project's key is refused outright — that is deliberate.

Where does Intern keep its own data?

In per-user app data. Your documents stay where they are. Uninstalling removes the app but leaves both your documents and Intern's data alone.

Can I use it fully offline?

Yes — after install and the model download, or by using Choose existing model files with a copy of the model from another machine. OneDrive folders keep working locally and sync whenever the sync client next connects.

10. Updates

Settings → Check for updates. Only when you ask — there is no background polling and no timer. An update installs only if it is signed by this project's key; anything else is refused.
