# Intern v0.1.0-alpha.7

This is an alpha release for Windows x86-64. It is deliberately published as a
GitHub **latest** release—not a GitHub prerelease—so installed alpha.6 clients
can continue to fetch the updater manifest at `/releases/latest/download/latest.json`.
The version and this note still make its alpha status explicit.

## Since alpha.6

Most of this release is about what happens around a proposed name: the date the
document is filed under, the spellings you prefer, the folder it lands in, and
whether Intern has seen the document before. Two changes are larger than that,
and both are choices someone has to make deliberately: a hosted model, and a
verified Microsoft uploader for shared intake folders.

- **Every rename carries a date.** A name that does not start with the
  document's date as `YYYY-MM-DD` is refused, in the inspector and again in the
  queue, so no path files an undated document. Getting one is a click: a date
  the model read but Intern could not find written in the document is shown as
  exactly that, with **Use this date** and **Use date & rename**; when the model
  offered none, every date the document states appears as a chip under the
  filename, the file's own last-modified date last and labelled as not being
  from the document. The date a person gives is the date the document is filed
  under — the year folder, the description record, and the shared filed index
  follow it rather than the one validation withheld.
- **Spellings Intern learns from you.** The document says "Vistage Worldwide,
  Inc." and you call it "Vistage". Respell a party or a document type in
  review, and the second time you make the same change it becomes the spelling
  Intern uses, in the name, the layout folder, and the description record. One
  edit is a decision about one document; two are a preference. Settings lists
  everything learned, with **Use now** and **Forget**, both taking effect at
  once on the documents still waiting. The evidence panel keeps the document's
  own words either way: a learned spelling changes what Intern calls a thing,
  never what it found.
- **Filed documents can be arranged into subfolders.** **Arrange filed
  documents** in Settings files by year, by year and type, by type, or by first
  party; flat remains the default. Folders are created as documents arrive and
  removed by the undo that empties them, and a document missing the fact a
  layout keys on goes to `Undated` or `Unsorted` rather than the destination
  root, so what still needs a hand stays visible. Collisions are checked in the
  folder the document is going to, so a ` (2)` suffix means a real collision.
- **The same document twice.** Identical bytes were already caught, but a
  second scan of the same page, a PDF exported twice, or a copy saved again
  with new metadata is not identical bytes. Intern now fingerprints the text it
  extracted and holds every new document against what it has filed — on this
  machine, and through a filed index in the intake folder's `.intern/`
  directory, on teammates' machines too. Closeness alone does not decide: this
  month's statement and last month's share almost every word, so the dates have
  to agree as well. A near-duplicate waits in review, named after the filing it
  repeats and the machine that made it, and is never filed on its own.
- **The one-sentence description can reach a SharePoint column.** With **Write
  a description record for each filed document** on, every rename into the
  destination also writes a small JSON record under
  `<destination>\.intern\descriptions\`: the filename, its path in the library,
  the sentence, and the date, type, and parties behind the name — never
  document text. The sync client uploads it like any other file, and a Power
  Automate flow copies the sentence into a **Description** column; the recipe
  is in
  [`docs/sharepoint-descriptions.md`](https://github.com/zgbrenner/intern/blob/main/docs/sharepoint-descriptions.md).
  Undo retracts the record, Settings can write records for documents filed
  before the setting was on, and the history CSV export carries the same
  sentence for anyone who would rather paste. Intern makes no network request
  for any of it.
- **Finding the folder, and folders on a network share.** Settings lists the
  synced locations the sync client keeps on this machine — every SharePoint
  library and OneDrive account, with its local folder — and fills the intake or
  destination field from one click, instead of a hunt through a folder dialog
  for `C:\Users\pat\Contoso\Legal - Documents`. A UNC path or mapped drive is
  recognised and labelled *On a network share*, and machines watching a share
  coordinate through the same `.intern/` claim files. A subfolder the account
  cannot read is counted and skipped instead of stopping the scan.
- **Outlook messages and PowerPoint decks.** Dragging a message out of Outlook
  produces a `.msg` file, which Intern now reads natively, into the same page
  an `.eml` becomes. `.pptx`, `.pptm`, and `.ppsx` decks are read too.
- **Naming accuracy, and a number that holds it.** What *kind* of date a date
  is now comes from the document's own wording around it (`Effective Date:`,
  `Invoice date`, `Notice is hereby given ... on`) rather than the model's
  habit; a document the model could not type but whose title names one is named
  from the title and sent to review with the reason shown; an invoice proposed
  as being between two sides is repaired to being from its issuer when the
  layout names one. Dates are matched in more of the spellings documents
  actually use, and only as whole tokens, so `12/1/2026` no longer supports
  February 1. All of it is measured now: CI replays a committed recording of
  what the parser read and what the model answered, and fails when a fact that
  used to be right is wrong. Date role, the weakest measure in alpha.6 at 6 of
  13, is 13 of 14; type is 18 of 18, parties 15 of 19, and nothing was filed
  under a corpus-marked trap date.
- **A hosted model, if you choose one.** Settings can point Intern at a hosted
  model under your own API key — Anthropic's, OpenAI's, or anything speaking
  the OpenAI chat-completions shape, including a local server such as Ollama or
  LM Studio. It is off by default, and it is the one setting that sends the
  condensed text of your documents off this computer: while it is on the header
  badge reads *Hosted model · Text leaves this device* instead of *Private · On
  this device*. The key lives in Windows' credential store rather than in any
  Intern file, **Test connection** sends only Intern's own calibration
  document, and a document a hosted model declines to answer about goes to
  review rather than being quietly re-routed to another model. If Intern's
  promise is why you use it, leave this off.
- **Shared intake now asks who uploaded a document — read this before upgrading
  if you watch a folder.** A file appearing on this machine is not evidence
  that this machine's user uploaded it, so a watched intake folder is processed
  only for an uploader verified against Microsoft's own record of the upload.
  That changes an existing setup: until you either connect Microsoft upload
  verification in Settings or mark an ordinary folder as **a private local
  intake, not a shared or synced folder** — deliberately not offered for a
  OneDrive, SharePoint, or network folder — documents in the watched folder are
  held and counted as *uploader unknown*. Documents dragged onto the window
  from anywhere else are unaffected. Connecting is not yet a plain sign-in: it
  needs an administrator, a tenant application registration, workload-wide
  audit read permissions, and the library's drive and folder IDs, and Microsoft
  usually publishes the audit evidence 60 to 90 minutes after an upload, during
  which the document waits. The connector admits new, unchanged work or school
  uploads from the last seven days; personal OneDrive, moves, copies,
  overwrites, and ambiguous evidence stay held. It is a pilot, tested against
  synthetic responses rather than a live tenant;
  [`docs/microsoft-upload-verification.md`](https://github.com/zgbrenner/intern/blob/main/docs/microsoft-upload-verification.md)
  has the setup, the permissions, and the limits.
- **A queue that says when it has lost touch.** A failed read used to blank the
  queue; it now keeps the rows it had, explains the failure, and offers **Retry
  queue connection**. A slow read can no longer overwrite a newer one, a late
  progress event can no longer turn a settled row back into a processing one,
  and a failure to open a picker, resolve a drop, or import a folder is
  reported in the same place as every other failure instead of vanishing. Two
  drops of the same folder in quick succession no longer race each other.
- **Two small things in the window.** A queue longer than six items gets a
  filter box above it that narrows the rows by original name, proposed name, or
  a word from the description. The tray icon's tooltip now says how many
  documents need review and how many are ready to rename, so a glance answers
  whether the window is worth opening.

## Download, model, and update details

Supported target: **Windows 10 or 11, x86-64**, using the per-user NSIS
installer `Intern_0.1.0-alpha.7_x64-setup.exe`. It does not require administrator
rights. The installer contains the local parser/runtime but not the 1.19 GiB
local text model; first run downloads that pinned model only after user action,
or lets you choose an existing verified copy. With the local model — the
default — document text, OCR output, and prompts stay on the machine, and using
a OneDrive or SharePoint-synced folder only uses the sync client already
configured on it. The two optional integrations above are the exceptions, and
neither does anything until someone turns it on: a hosted model receives the
distilled text of each document, and Microsoft upload verification sends item
paths and time ranges to Microsoft and reads identity, metadata, and audit
records, never document text.

Use **Check for updates** in Settings to fetch GitHub's latest manifest. The
client installs only an updater payload whose detached Minisign signature
verifies against the public key compiled into the application. The release
workflow independently verifies the exact installer, detached signature, and
`latest.json` URL/version/signature binding before creating release evidence.

`SHA256SUMS.txt` covers every distributable release file exactly once, except
itself and `release-evidence-manifest.json` to avoid a checksum cycle. The
evidence manifest hashes the checksum file and binds the installer, updater
manifest, runtime inventory, notices, SBOMs, smoke/evaluation/fidelity evidence,
and logs. Verify the installer provenance as well:

```sh
gh attestation verify Intern_0.1.0-alpha.7_x64-setup.exe --repo zgbrenner/intern
```

The installer is **not Authenticode signed**: this project has no Windows
code-signing certificate. Windows/SmartScreen may warn about an unrecognized
app even when the updater signature and GitHub provenance check pass. Treat the
warning seriously, verify the checksum and provenance, then use **More info** →
**Run anyway** only if you trust the release.
