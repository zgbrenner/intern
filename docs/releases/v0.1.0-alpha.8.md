# Intern v0.1.0-alpha.8

This is an alpha release for Windows x86-64. It is deliberately published as a
GitHub **latest** release—not a GitHub prerelease—so installed clients can
continue to fetch the updater manifest at
`/releases/latest/download/latest.json`. The version and this note still make
its alpha status explicit.

## Since alpha.6

alpha.7 was prepared but never published, so everything in
[its notes](v0.1.0-alpha.7.md) ships here too: dates on every rename, learned
spellings, subfolder layouts, near-duplicate detection, descriptions in a
SharePoint column, Outlook messages and PowerPoint decks, an optional hosted
model, and the Microsoft upload verification pilot.

This release is about none of that. It is a reliability pass: eight reviews
read the code against the architecture it claims to implement, and nine
rounds of work fixed what they found, each with a test written first that
failed for the stated reason. The corpus went up and nothing regressed.

### Documents no longer get stuck

- **A rename interrupted at the wrong moment no longer freezes everything.**
  If the machine lost power between the file being renamed and Intern writing
  that down, the document stayed mid-apply for ever—and because Intern only
  works on one document at a time, every other document waited behind it. There
  was no way out but editing Intern's database by hand. Recovery now finishes
  the case it can prove, and parks anything genuinely ambiguous in review,
  naming both files so you can decide. The queue keeps moving either way.
- **Undo stays undone.** With automatic renaming on, undoing a rename put the
  document back in the queue as ready to file, and the next pass filed it
  again within the minute. An undone document now waits for you.
- **Approving while Intern is working now works.** It used to refuse and push
  the document into review with a message that explained nothing. The approval
  is now remembered, survives a restart, and is applied as soon as the document
  in progress finishes.
- **Renames that completed during recovery are recorded properly**, so the
  description record, the shared filed index, and duplicate detection all know
  about them. Previously a rename that finished this way was invisible to
  teammates and to Intern's own memory of what it had filed.

### The app stops when you close it

- **llama-server no longer survives the app.** Closing the window with
  background mode off left the local model running—well over a gigabyte of
  memory—until the machine was rebooted, and the next launch started another
  one. The parser worker did the same. Both are now tied to Intern's own
  process at the operating-system level, so they stop when it does, including
  when it crashes.
- **Updating is no longer racing itself.** The same defect meant the installer
  could be asked to replace files that were still open.
- **Only one Intern runs at a time.** Autostart plus a click on the shortcut
  used to start a second copy, with its own model and its own view of the same
  queue. A second launch now brings the existing window forward.
- **The window opens immediately.** Intern used to verify the local model—
  starting it, waiting for it, and running a full test document through it—
  before the window could draw, so every launch began with an unresponsive
  rectangle. Verification now happens behind the window, and the queue waits
  for it rather than failing documents.

### Privacy and correctness in the optional integrations

- **A hosted model on your own machine no longer goes through a proxy.**
  Intern accepts plain HTTP only to this computer, so a local server such as
  Ollama or LM Studio can be used without a certificate. On a machine
  configured with a corporate proxy, those requests were being handed to the
  proxy anyway—API key and document text in the clear. They are not any more.
  If you have used a local hosted model on a machine with a proxy configured,
  treat that key as exposed and replace it.
- **Microsoft upload verification is usable.** Accepted evidence about who
  uploaded a document lasted sixty seconds, while every stage of processing
  asked again—so any document taking longer than a minute was thrown back into
  review, and a folder of documents could barely be filed at all. One routine
  "not found" for a file that had not finished syncing blocked every other
  file for ten seconds. A momentary network problem was read as the upload
  being revoked, and cancelled work already under way. All of that is fixed,
  and it is still fail-closed: an upload Intern cannot verify is still held.
- **A shared folder no longer files a sync conflict copy as a second
  document**, and a machine that is still working is no longer treated as
  crashed because its clock is wrong.

### Documents Intern could not read, or read wrongly

- **A spreadsheet with two far-apart cells no longer kills the parser.** Nor
  does an email with an unusual character in it, an email with deeply nested
  attachments, or a message whose formatting claims to expand to four
  gigabytes.
- **A scan whose only machine-readable text is a stamp is now read.** A
  document stamped "CONFIDENTIAL - SUBJECT TO PROTECTIVE ORDER" over an image
  of a page counted as having text, so it was never sent to OCR and Intern saw
  a stamp and nothing else.
- **A large-format page with real text is no longer rejected.** An A2 drawing
  or plan was refused for being too large to render, even when nothing needed
  rendering.
- **A text file saved as Unicode by Notepad is read** instead of failing.
- **A multi-page fax now says how many pages were not read**, rather than
  silently filing the first one as the whole document.

### Naming accuracy

Measured by replaying the recorded corpus, which is how every accuracy claim
in this project is made:

| | alpha.7 | alpha.8 |
|---|---:|---:|
| Date role correct | 13/14 | **14/14** |
| Parties correct | 15/19 | **16/19** |
| Description specific | 18/19 | **19/19** |
| Agreed with the corpus on review-or-name | 17/19 | **18/19** |
| Filed under a date the corpus marks as a trap | 0 | **0** |
| Review rate | 47% | **42%** |

Document type stayed 18/18 and no document scored worse than before.

Two of those gains were Intern's own bugs, not the model's. A description
containing an amount like `$1,248.00` was being cut in half at the decimal
point and then rejected for not being a sentence—and the project's own notes
blamed the model for text Intern had mangled. A document with a one-sided
relationship, such as a notice *to* someone, kept a second party the filename
never uses.

Beyond that: a date belonging to a *different* agreement that a PDF happened
to wrap onto two lines is once again recognised as a reference rather than
this document's date; a cover page that dates itself is read; a payment due
date can no longer be labelled as an invoice date; and a quotation is checked
against whole words, so "John Smith" is no longer supported by a document that
says "John Smithson".

### In the window

- **Typing is no longer interrupted.** Every time the queue reported progress,
  Settings and History pulled the cursor back to their first field—so
  keystrokes meant for an API key or a folder path ended up in another box.
- **Pause and Resume work.** On the installed app the buttons threw an error
  and did nothing.
- **The queue says when it has stopped and why**, instead of quietly sitting
  still after a hosted model rejects a key.
- **Dropped files report their errors**, a cancelled file dialog no longer
  disables the buttons, and a failure to refresh the list after a successful
  rename is no longer reported as the rename having failed.
- **The webview has a content security policy** for the first time.

## Download, model, and update details

Supported target: **Windows 10 or 11, x86-64**, using the per-user NSIS
installer `Intern_0.1.0-alpha.8_x64-setup.exe`. It does not require
administrator rights. The installer contains the local parser/runtime but not
the 1.19 GiB local text model; first run downloads that pinned model only after
user action, or lets you choose an existing verified copy. The model download
is now pinned to an immutable upstream revision, has no overall time limit that
a slow connection could never meet, and a corrupted copy is replaced rather
than becoming permanently unusable.

With the local model—the default—document text, OCR output, and prompts stay on
the machine. The two optional integrations remain the exceptions, and neither
does anything until someone turns it on: a hosted model receives the distilled
text of each document, and Microsoft upload verification sends item paths and
time ranges to Microsoft and reads identity, metadata, and audit records, never
document text.

Use **Check for updates** in Settings to fetch GitHub's latest manifest. The
client installs only an updater payload whose detached Minisign signature
verifies against the public key compiled into the application. The release
workflow independently verifies the exact installer, detached signature, and
`latest.json` URL/version/signature binding before creating release evidence.

`SHA256SUMS.txt` covers every distributable release file exactly once, except
itself and `release-evidence-manifest.json` to avoid a checksum cycle. The
evidence manifest hashes the checksum file and binds the installer, updater
manifest, runtime inventory, notices, SBOMs, smoke/evaluation/fidelity evidence,
and logs. Verify the installer provenance as well:

```sh
gh attestation verify Intern_0.1.0-alpha.8_x64-setup.exe --repo zgbrenner/intern
```

The installer is **not Authenticode signed**: this project has no Windows
code-signing certificate. Windows/SmartScreen may warn about an unrecognized
app even when the updater signature and GitHub provenance check pass. Treat the
warning seriously, verify the checksum and provenance, then use **More info** →
**Run anyway** only if you trust the release.
