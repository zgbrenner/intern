# Intern v0.1.0-alpha.6

This is an alpha release for Windows x86-64. It is deliberately published as a
GitHub **latest** release—not a GitHub prerelease—so installed alpha.5 clients
can continue to fetch the updater manifest at `/releases/latest/download/latest.json`.
The version and this note still make its alpha status explicit.

## Since alpha.5

This release is about the moment a person decides whether to trust a proposed
name, and about being able to find out how Intern works without asking anyone.

- **The review inspector, rebuilt around the decision it exists for.** Evidence
  was a definition list: three rows of run-together text that read like fields
  in a database rather than support for a claim. Each piece of evidence is now
  an attributed quotation, labelled with the part of the filename it justifies,
  so the date, the type, and each party can be checked one at a time. The
  confidence the model reported now appears in the panel; it previously existed
  only in the queue table, so the surface where a person decides whether to
  trust a name never showed how sure the model was. The approve/keep decision
  bar is pinned to the bottom of the panel, so it no longer scrolls out of
  reach behind long evidence.
- **A first run that explains itself.** An empty queue was four column headings
  and nothing under them. It now says what to do, what happens to a document
  once it is dropped, and which formats are supported: PDF, DOCX, XLSX, EML,
  TXT, Markdown, PNG, JPEG, and TIFF. A filtered view that is empty while the
  queue is not gets its own copy, so opening **Needs review** and finding it
  blank says that Intern asks for a person only when the evidence behind a name
  is thin, rather than leaving you unsure whether the click registered.
- **Two status bugs.** `.status.failed` had no colour defined, so the one status
  a person most needs to spot rendered as ordinary body text. Hover and
  selection shared a colour, so the row under the pointer claimed to be the row
  the inspector was describing. Both are fixed.
- **Settings grouped** into Filing, This computer, Shared intake, Updates, and
  Help & support. Each group opens with a plain-language line naming the
  decision it settles, and Save is pinned to a footer instead of sitting
  somewhere in the middle of one long column of controls.
- **Help & support opens the guide.** It opens
  <https://zgbrenner.github.io/intern/guide.html> in your own browser, through a
  Tauri capability scoped to that one site rather than a general open-anything
  permission, so nothing in the interface can ask the shell to open an address
  of its choosing.
- **A guide, and a redesigned site.** <https://zgbrenner.github.io/intern> now
  covers installing, first launch, your first document, everyday use, OneDrive
  and SharePoint, watched folders, several computers sharing one folder, and
  troubleshooting, in the order a first-time user meets them. Diagrams carry the
  explanation where paragraphs used to: a filename anatomy diagram resolving one
  messy name into a dated, typed, attributed one; a boundary diagram drawing
  your machine as a box with exactly two labelled arrows crossing it; and a
  topology diagram drawing the connection Intern does not make as a crossed-out
  line to Microsoft's servers. Troubleshooting is symptom-first, phrased the way
  someone would describe the problem.
- **Licensing, stated plainly.** Intern is source-available under the
  [Elastic License 2.0](https://github.com/zgbrenner/intern/blob/main/LICENSE),
  © 2026 Vistage Worldwide, Inc. Read, audit, build, run, modify, and
  redistribute it; what the license reserves is providing Intern to third
  parties as a hosted or managed service. The audit right is the part that
  matters here: this product's claims about what never leaves your machine are
  worth only as much as a reader's ability to check them against the source.

## Download, model, and update details

Supported target: **Windows 10 or 11, x86-64**, using the per-user NSIS
installer `Intern_0.1.0-alpha.6_x64-setup.exe`. It does not require administrator
rights. The installer contains the local parser/runtime but not the 1.19 GiB
local text model; first run downloads that pinned model only after user action,
or lets you choose an existing verified copy. Document text, OCR output, and
prompts stay local; using a OneDrive or SharePoint-synced folder only uses the
sync client already configured on the machine.

Use **Check for updates** in Settings to fetch GitHub's latest manifest. The
client installs only an updater payload whose detached Minisign signature
verifies against the public key compiled into the application. The release
workflow independently verifies the exact installer, detached signature, and
`latest.json` URL/version/signature binding before creating release evidence.

`SHA256SUMS.txt` covers every distributable release file exactly once, except
itself and `release-evidence-manifest.json` to avoid a checksum cycle. The
evidence manifest hashes the checksum file and binds the installer, updater
manifest, runtime inventory, notices, SBOMs, smoke/evaluation/fidelity evidence,
and logs. Verify the installer provenance as well:

```sh
gh attestation verify Intern_0.1.0-alpha.6_x64-setup.exe --repo zgbrenner/intern
```

The installer is **not Authenticode signed**: this project has no Windows
code-signing certificate. Windows/SmartScreen may warn about an unrecognized
app even when the updater signature and GitHub provenance check pass. Treat the
warning seriously, verify the checksum and provenance, then use **More info** →
**Run anyway** only if you trust the release.
