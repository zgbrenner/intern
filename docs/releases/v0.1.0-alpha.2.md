# Intern v0.1.0-alpha.2

## What changed since v0.1.0-alpha.1

- **Descriptions are visible.** The one-sentence description of each document now appears under its proposed filename in the queue, and stays available after a rename is applied. Previously it was rendered only while an item was awaiting a decision, so it disappeared at the moment the document was filed.
- **A large folder can be abandoned.** Pointing the queue at the wrong directory used to be unrecoverable from inside the app: pausing left the backlog, clearing history only removed finished items, and dropping a waiting item took one click each. **Discard waiting** removes everything that has not started, and nothing else — work in progress finishes, items awaiting your decision stay, and applied renames keep the receipts that make undo work.
- **The in-app updater works.** Settings has a **Check for updates** button that asks GitHub for the release manifest and installs only an update signed by this project's key. It never checks on its own schedule. In v0.1.0-alpha.1 that check returned 404, because GitHub resolves `/releases/latest` to the newest release that is not a prerelease, and that release was published as one.

Intern still makes exactly two network requests, both started by pressing a button: the one-off model download, and this update check. Neither carries anything about your documents.

## About this release

This testing release processes documents locally. Intern does not upload document contents or filenames to a hosted service. Network access is used only when the user explicitly downloads the optional model during setup.

The Windows installer intentionally excludes model weights. The pinned Q4 text model is 1,280,835,840 bytes (about 1.19 GiB) and is the only file setup downloads; Intern verifies its exact length and SHA-256 before use. There is no vision projector.

This alpha installer is **not** Authenticode signed, because no code-signing certificate exists for this project. Windows SmartScreen will show an “unrecognized app” warning, and nothing in this release removes it.

What the release does give you is provenance. Every published installer carries a GitHub build-provenance attestation, signed keylessly through Sigstore by the workflow that built it, so you can prove the bytes you downloaded came from this repository at a specific commit:

```sh
gh attestation verify Intern_0.1.0-alpha.2_x64-setup.exe --repo zgbrenner/intern
```

`SHA256SUMS.txt` is published alongside the installer and detects a corrupted or truncated download. On its own it proves nothing about origin — it sits on the same page as the installer, so anyone able to replace one could replace both. The attestation is the part that establishes where the file came from.

The release includes the per-user NSIS installer, third-party notices, complete runtime license texts, a validated SPDX SBOM set, and checksums. Uninstalling the app does not remove the user’s documents or Intern user data.
