# Intern v0.1.0-alpha.9

This is an alpha release for Windows x86-64. It is deliberately published as a
GitHub **latest** release—not a GitHub prerelease—so installed clients can
continue to fetch the updater manifest at
`/releases/latest/download/latest.json`. The version and this note still make
its alpha status explicit.

## Since alpha.8

alpha.8 was the first release of the reliability work; this one is what testing
the shipped build found afterwards. Everything here came from running the
published installer against real documents and a real OneDrive folder, rather
than from reading the code.

### A shared folder that actually keeps working

Most of this release is about the folder several machines watch together—a
SharePoint library, a OneDrive folder, or a network share.

- **A teammate's crash no longer strands a document for ever.** When a machine
  claims a document and then dies, its claim stays in the folder. Every other
  machine counted that as "someone is working on this" and skipped the document,
  so nobody ever filed it. Intern now takes over a claim whose owner has been
  silent for a full lease, and the rescued document goes through exactly the same
  uploader check as any other, so nothing is admitted that would not have been.
- **Antivirus and the sync client no longer break a claim.** The small files
  Intern uses to coordinate live inside the watched folder, so the sync client,
  Windows Search and any antivirus filter all open them. While one of them holds
  a file, Windows refuses to replace it, and a claim that could not be renewed
  stranded the document it was holding. Intern now waits those holds out—the same
  way it already waited them out on your documents themselves.
- **More sync conflict copies are recognised.** OneDrive names the losing side of
  a conflict after the machine that wrote it, sometimes with a counter or a date
  as well. The numbered and dated forms were being filed as second documents.
  They are left alone now, and a document whose name merely ends in `(2)` is
  still an ordinary document.
- **A conflict copy of Intern's own record no longer confuses it.** A conflicted
  copy of a machine's presence record made one machine look like two, and a
  conflicted copy of a filing marker made an undone rename keep flagging fresh
  documents as duplicates.
- **A retracted description is retracted everywhere.** Undoing a rename removed
  the description record Intern wrote for it, but not the copies a sync client
  may have made of it. A leftover copy meant the SharePoint column could still be
  filled in for a document that is no longer filed.

### A setting that says it is local no longer means it is trusted for ever

**This one is worth reading if you use a watched folder.** Intern only processes
a shared folder for an uploader it can verify against Microsoft's own record.
There is one exception: a folder you have marked as a private local intake, which
Intern does not offer for a OneDrive, SharePoint, or network folder.

That exception was checked when you saved the setting, and then believed
indefinitely. So a folder configured as a private local intake and *later* moved
into OneDrive—or a folder that starts syncing where it stands—kept the exception
it was granted when it was genuinely local. From then on, documents other people
synced into it were processed as though you had put them there.

Intern now decides that per folder, as it works, rather than trusting what was
stored. A folder that has become shared is held, and Settings says so and what to
do about it. If you configured a private local intake before this release, check
that it is still the folder you meant.

### Opening the window

- **A narrow window opens on your queue.** At 1100 pixels wide or less—including
  1024, the narrowest size Intern supports—the window used to open inside a
  review drawer covering the queue, with the cursor already in a filename box
  nobody had asked to edit. It now opens on the queue. Clicking a document still
  opens the drawer, exactly as before.

### A settings file that cannot be read

- **Intern says so instead of quietly forgetting everything.** A settings file it
  could not parse was silently replaced by defaults: no destination, no watched
  folder, automatic renaming off. The app looked configured for nothing, filed
  nothing, and said nothing. It now keeps every setting it *can* read, names the
  ones it could not, and tells you in Settings. The file is not written over until
  you deliberately save.
- **A byte-order mark no longer breaks it.** Windows tooling adds one to a UTF-8
  file by default; `Set-Content -Encoding utf8` in Windows PowerShell is enough to
  do it. That alone made the whole file unreadable.
- **One bad value no longer discards the rest.** A single misspelled setting used
  to take your destination and watched folder down with it.

## Download, model, and update details

Supported target: **Windows 10 or 11, x86-64**, using the per-user NSIS
installer `Intern_0.1.0-alpha.9_x64-setup.exe`. It does not require
administrator rights. The installer contains the local parser/runtime but not
the 1.19 GiB local text model; first run downloads that pinned model only after
user action, or lets you choose an existing verified copy.

With the local model—the default—document text, OCR output, and prompts stay on
the machine. The two optional integrations remain the exceptions, and neither
does anything until someone turns it on: a hosted model receives the distilled
text of each document, and Microsoft upload verification sends item paths and
time ranges to Microsoft and reads identity, metadata, and audit records, never
document text.

Use **Check for updates** in Settings to fetch GitHub's latest manifest. The
client installs only an updater payload whose detached Minisign signature
verifies against the public key compiled into the application. The release
workflow independently verifies the exact installer, detached signature, and
`latest.json` URL/version/signature binding before creating release evidence.

`SHA256SUMS.txt` covers every distributable release file exactly once, except
itself and `release-evidence-manifest.json` to avoid a checksum cycle. The
evidence manifest hashes the checksum file and binds the installer, updater
manifest, runtime inventory, notices, SBOMs, smoke/evaluation/fidelity evidence,
and logs. Verify the installer provenance as well:

```sh
gh attestation verify Intern_0.1.0-alpha.9_x64-setup.exe --repo zgbrenner/intern
```

The installer is **not Authenticode signed**: this project has no Windows
code-signing certificate. Windows/SmartScreen may warn about an unrecognized
app even when the updater signature and GitHub provenance check pass. Treat the
warning seriously, verify the checksum and provenance, then use **More info** →
**Run anyway** only if you trust the release.
