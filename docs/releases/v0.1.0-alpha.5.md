# Intern v0.1.0-alpha.5

This is an alpha release for Windows x86-64. It is deliberately published as a
GitHub **latest** release—not a GitHub prerelease—so installed alpha.4 clients
can continue to fetch the updater manifest at `/releases/latest/download/latest.json`.
The version and this note still make its alpha status explicit.

## Since alpha.4

This release is about being understood: by the model, by the person reviewing
a name, and by anyone deciding whether to install Intern at all.

- **Naming accuracy: the model is finally told what a date role is.** The
  grammar has always forced `date_role` into nine values, but the prompt never
  explained them and its answer skeleton pre-filled `"effective"` — so the
  model answered "effective" for invoices, notices, minutes, and amendments
  alike. The prompt now defines every role and the skeleton no longer answers
  the question for it. Alongside that: invoices and packing slips are pinned
  to exactly one party (the issuer — never the bill-to), a first name alone is
  never a party, and the model is told to use the document's own words for the
  type — a document headed "Quarterly Operations Review" is not "Meeting
  Minutes". Every one of these rules is pinned by a prompt regression test,
  and the release evaluation measures them against the corpus with real
  inference before anything is published.
- **Review reasons in sentences.** The inspector said `SOURCE_LOCKED` or
  `TYPE_UNSUPPORTED, LOW_CONFIDENCE`; it now says what happened and what to do
  — "Another program is still holding this file open — often a sync client
  mid-upload. Retry once it settles." Unknown codes still pass through
  unchanged rather than being dressed up.
- **Vistage branding.** Intern is built for Vistage, and now says so: a quiet
  "for Vistage" tag beside the wordmark, primary actions in Vistage navy, and
  brand-consistent selection and focus states. The accessibility contrast
  gates run in CI and every pair stays at or above 4.5:1 — the selected-row
  tint was specifically chosen because the first candidate dropped the
  "Needs review" amber to 4.19:1.
- **A download page that explains itself.** <https://zgbrenner.github.io/intern>
  now opens with real before-and-after renames, walks through how Intern works
  in three steps, and states the privacy posture plainly — everything on your
  machine, exactly two user-initiated network requests, OneDrive and
  SharePoint through the sync client you already run. The SmartScreen warning
  and the provenance-verification command remain front and center, unsoftened.

## Download, model, and update details

Supported target: **Windows 10 or 11, x86-64**, using the per-user NSIS
installer `Intern_0.1.0-alpha.5_x64-setup.exe`. It does not require administrator
rights. The installer contains the local parser/runtime but not the 1.19 GiB
local text model; first run downloads that pinned model only after user action,
or lets you choose an existing verified copy. Document text, OCR output, and
prompts stay local; using a OneDrive or SharePoint-synced folder only uses the
sync client already configured on the machine.

Use **Check for updates** in Settings to fetch GitHub's latest manifest. The
client installs only an updater payload whose detached Minisign signature
verifies against the public key compiled into the application. The release
workflow independently verifies the exact installer, detached signature, and
`latest.json` URL/version/signature binding before creating release evidence.

`SHA256SUMS.txt` covers every distributable release file exactly once, except
itself and `release-evidence-manifest.json` to avoid a checksum cycle. The
evidence manifest hashes the checksum file and binds the installer, updater
manifest, runtime inventory, notices, SBOMs, smoke/evaluation/fidelity evidence,
and logs. Verify the installer provenance as well:

```sh
gh attestation verify Intern_0.1.0-alpha.5_x64-setup.exe --repo zgbrenner/intern
```

The installer is **not Authenticode signed**: this project has no Windows
code-signing certificate. Windows/SmartScreen may warn about an unrecognized
app even when the updater signature and GitHub provenance check pass. Treat the
warning seriously, verify the checksum and provenance, then use **More info** →
**Run anyway** only if you trust the release.
