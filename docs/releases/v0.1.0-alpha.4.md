# Intern v0.1.0-alpha.4

This is an alpha release for Windows x86-64. It is deliberately published as a
GitHub **latest** release—not a GitHub prerelease—so installed alpha.3 clients
can continue to fetch the updater manifest at `/releases/latest/download/latest.json`.
The version and this note still make its alpha status explicit.

## Since alpha.3

Three defects in the watched-intake path, all of them things a OneDrive or
SharePoint folder does routinely and a local folder never does.

- **A sync client holding a file open no longer looks like a corrupted
  document.** OneDrive locks a file while it uploads it, and Windows refuses
  the open with `ERROR_SHARING_VIOLATION`. Intern reported that as
  `FILE_CHANGED` and sent an intact document to review, discarding the
  operating system's error on the way. It now waits the lock out — five
  attempts over about three seconds — and a file still held after that is
  reported as `SOURCE_LOCKED` with the OS error carried into the message.
- **Sync conflict copies are no longer filed as new documents.** A conflict
  copy is the sync client's bookkeeping, not something a person put in the
  folder; naming one put a second copy of an already-filed document into the
  destination. The spelled-out `(… conflicted copy …)` form is recognised
  outright; the machine-suffix form is believed only when it names a machine
  the shared folder has actually seen, so `Invoice-ACME.pdf` is still an
  ordinary document. Settings counts what was skipped.
- **A document that failed while its content was still in the cloud is no
  longer tombstoned.** Nothing had read it, so there was no verdict to record,
  and the tombstone outlived the trip that caused it. The claim is now held
  open and released for a fresh attempt once the bytes arrive. A second
  failure with the content local is a real failure and is recorded as one.

A download page for the installer is now published at
<https://zgbrenner.github.io/intern>.

Everything above is local behavior. Intern still makes exactly the two
user-initiated network requests it always made, and still has no Graph API
client, OAuth token, or upload code: OneDrive and SharePoint are reached only
through the folders the Microsoft sync client already keeps on disk.

## Download, model, and update details

Supported target: **Windows 10 or 11, x86-64**, using the per-user NSIS
installer `Intern_0.1.0-alpha.4_x64-setup.exe`. It does not require administrator
rights. The installer contains the local parser/runtime but not the 1.19 GiB
local text model; first run downloads that pinned model only after user action,
or lets you choose an existing verified copy. Document text, OCR output, and
prompts stay local; using a OneDrive or SharePoint-synced folder only uses the
sync client already configured on the machine.

Use **Check for updates** in Settings to fetch GitHub's latest manifest. The
client installs only an updater payload whose detached Minisign signature
verifies against the public key compiled into the application. The release
workflow independently verifies the exact installer, detached signature, and
`latest.json` URL/version/signature binding before creating release evidence.

`SHA256SUMS.txt` covers every distributable release file exactly once, except
itself and `release-evidence-manifest.json` to avoid a checksum cycle. The
evidence manifest hashes the checksum file and binds the installer, updater
manifest, runtime inventory, notices, SBOMs, smoke/evaluation/fidelity evidence,
and logs. Verify the installer provenance as well:

```sh
gh attestation verify Intern_0.1.0-alpha.4_x64-setup.exe --repo zgbrenner/intern
```

The installer is **not Authenticode signed**: this project has no Windows
code-signing certificate. Windows/SmartScreen may warn about an unrecognized
app even when the updater signature and GitHub provenance check pass. Treat the
warning seriously, verify the checksum and provenance, then use **More info** →
**Run anyway** only if you trust the release.
